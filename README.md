# 楽天トラベル 空室監視

楽天トラベルの「空室のある宿の件数」を **5分ごと** に確認し、
前回から **件数が変わったときだけ** メールで知らせます。

- 動作場所は **GitHub Actions（クラウド）**。自分のPCの電源が切れていても動きます
- ブラウザは使いません。楽天へのログインも不要です
- 使うサービスはすべて **無料枠のみ**（GitHub / Gmail / Yahoo!メール）
- メールの文面は `templates/` のファイルを書き換えるだけで自由に変えられます

初期設定では **青森市周辺・2026年9月20日〜21日・大人2名1部屋** を監視します。

## 仕組み

```
GitHub Actions（5分ごと）
        ↓
楽天トラベルの検索結果を取得（件数と宿の一覧）
        ↓
前回の結果（state/ に保存）と比較
        ↓
   変化あり？ ──── いいえ ──→ 何もしない（メールは送らない）
        │
       はい
        ↓
Gmail から送信 ──→ Yahoo!メールで受信
        ↓
今回の結果を state/ に保存してコミット
```

### データの取り方

| 方式 | アプリID | 使いどころ |
|---|---|---|
| 検索ページのHTML | 不要 | **既定。GitHub Actions ではこちら** |
| 楽天ウェブサービスAPI | 必要 | アプリIDを設定すると自動的に優先される |

楽天ウェブサービスのAPIは登録時に **接続元IPアドレスの登録が必須** です。
GitHub Actions は実行のたびにIPが変わるため、クラウドではAPIを使えません。
そのため既定では、誰でもアクセスできる検索ページから件数を読み取ります。

将来アプリIDが使えるようになったら、Secrets に `RAKUTEN_APPLICATION_ID` を
足すだけで自動的にAPI優先に切り替わります（失敗時はHTMLに自動で戻ります）。

1. GitHub アカウント（無料）
2. 送信用の Gmail アカウント
3. 受信用の Yahoo!メールアドレス

楽天のアカウントは **不要** です。

## セットアップ手順

### 手順1. Gmail のアプリパスワードを発行する

Gmail は通常のログインパスワードでは外部から送信できません。
**アプリパスワード** という専用の16桁のパスワードが必要です。

1. <https://myaccount.google.com/security> を開く
2. **2段階認証プロセス** を有効にする（未設定の場合。これが無いと次に進めません）
3. <https://myaccount.google.com/apppasswords> を開く
4. アプリ名に `楽天空室監視` などと入力して作成
5. 表示された **16桁の文字列** を控える（`abcd efgh ijkl mnop` のように4桁ずつ表示されます。空白は入れても入れなくても構いません）

> この画面は一度閉じると二度と表示されません。控え忘れたら削除して作り直してください。

### 手順2. GitHub にリポジトリを作る

1. <https://github.com/new> を開く
2. リポジトリ名を入力（例: `rakuten-vacancy-watch`）
3. **Public を選ぶ**（無料で5分間隔を回すために必要。理由は[無料枠について](#無料枠について)）
4. 「Create repository」

このフォルダの中身を、そのリポジトリにアップロードします。

```bash
git init
git add -A
git commit -m "楽天トラベル空室監視を追加"
git branch -M main
git remote add origin https://github.com/あなたのユーザー名/rakuten-vacancy-watch.git
git push -u origin main
```

> `.env` は `.gitignore` で除外されているので、パスワードがアップロードされることはありません。

### 手順3. GitHub Secrets を登録する

パスワードやメールアドレスは、コードではなく Secrets に入れます。
**Public リポジトリでも Secrets の中身は誰にも見えません。**

リポジトリのページで **Settings** → 左メニューの **Secrets and variables** →
**Actions** → **New repository secret** を押し、次の3つを登録します。

| Name | Secret（値） |
|---|---|
| `GMAIL_ADDRESS` | 送信元の Gmail アドレス |
| `GMAIL_APP_PASSWORD` | 手順1で発行した16桁 |
| `NOTIFY_TO` | 受信する Yahoo!メールアドレス（カンマ区切りで複数可） |

`RAKUTEN_APPLICATION_ID` は登録しなくて構いません（未設定ならHTML方式で動きます）。

### 手順4. Actions を有効にする

リポジトリの **Actions** タブを開き、ワークフローの実行を許可します。
（Public リポジトリでは初回に確認ボタンが出ることがあります）

## 動作確認

セットアップが終わったら、**必ずこの順で確認してください。**

### 1. 手動で1回動かす

**Actions** タブ → 左メニューの **空室監視** → 右上の **Run workflow** →
`dry_run` に **チェックを入れて** 実行。

メールは送られず、ログに現在の件数が表示されます。
ここで「取得成功（経路=html, 件数=1 ...）」と出れば取得は正常です。

### 2. メールが届くか確かめる

`dry_run` の **チェックを外して** もう一度 **Run workflow**。

初回は「初回実行のため通知しません」となり、現在の件数が基準として保存されます。
**この時点ではメールは届きません。これは正常です。**

以降、件数が変わったときだけメールが届きます。

### 3. Yahoo!メール側の設定（重要）

自動送信メールは **迷惑メールフォルダに振り分けられやすい** です。
最初のメールが届いたら（または届かないときは）以下を確認してください。

1. Yahoo!メールの **迷惑メールフォルダ** を見る
2. 見つかったら「迷惑メールではない」を選ぶ
3. **設定 → メールの管理 → 受信許可・拒否** で、送信元の Gmail アドレスを
   **受信許可リスト（セーフリスト）** に登録する

## メール文面のカスタマイズ

`templates/` の中のファイルを書き換えるだけで、件名も本文も自由に変えられます。
Python のコードを触る必要はありません。

| ファイル | 役割 |
|---|---|
| `templates/subject.txt` | 件名 |
| `templates/body.txt` | 本文（テキスト版） |
| `templates/body.html` | 本文（HTML版） |
| `templates/error_subject.txt` | 取得エラーが続いたときの件名 |
| `templates/error_body.txt` | 取得エラーが続いたときの本文 |

### 使える変数

| 変数 | 内容 | 例 |
|---|---|---|
| `{{ area_name }}` | 監視エリア名（`config.yaml` の `name`） | 青森市周辺 |
| `{{ checkin }}` | チェックイン日 | 2026-09-20 |
| `{{ checkout }}` | チェックアウト日 | 2026-09-21 |
| `{{ stay_label }}` | 短い日付表記 | 9/20-21 |
| `{{ nights }}` | 泊数 | 1 |
| `{{ adult_num }}` | 大人の人数 | 2 |
| `{{ room_num }}` | 部屋数 | 1 |
| `{{ prev_count }}` | 前回の件数 | 1 |
| `{{ curr_count }}` | 今回の件数 | 3 |
| `{{ diff }}` | 増減数（数値） | 2 |
| `{{ diff_text }}` | 符号付きの増減 | +2 |
| `{{ direction }}` | 増加 / 減少 / 入れ替わり | 増加 |
| `{{ direction_mark }}` | ▲ / ▼ / ◆ | ▲ |
| `{{ added_hotels }}` | 新しく空室が出た宿のリスト | |
| `{{ removed_hotels }}` | 空室がなくなった宿のリスト | |
| `{{ current_hotels }}` | 現在空室のある宿のリスト | |
| `{{ min_price }}` | 現在の最安料金（数値。無ければ `none`） | 12800 |
| `{{ min_price_text }}` | 最安料金の3桁区切り | 12,800 |
| `{{ search_url }}` | 楽天トラベルの検索結果URL | |
| `{{ now }}` | 実行日時（日本時間） | |

宿のリストは `for` でまわせます。各要素が持つ項目は次のとおりです。

| 項目 | 内容 |
|---|---|
| `h.name` | 宿名 |
| `h.price` | 料金（数値。不明なら `none`） |
| `h.price_text` | 料金の3桁区切り（不明なら `―`） |
| `h.url` | 宿のページURL |
| `h.review_text` | レビュー平均（不明なら `―`） |
| `h.hotel_no` | 楽天の宿番号 |

日時は `{{ now.strftime('%m/%d %H:%M') }}` のように書式を指定できます。

### 書き方の例

**その1：シンプルに件数だけ**

```
件名: 青森の宿 {{ prev_count }}→{{ curr_count }}件

{{ checkin }}の空室が{{ curr_count }}件になりました。
{{ search_url }}
```

**その2：増えた宿を並べる**

```
{{ direction }}しました（{{ prev_count }}件 → {{ curr_count }}件）

{% for h in added_hotels %}
・{{ h.name }} … {{ h.price_text }}円
{% endfor %}

{{ search_url }}
```

**その3：絵文字を使ってカジュアルに**

```
{% if diff > 0 %}🎉 空室が増えました！{% else %}😢 空室が減りました{% endif %}

{{ area_name }}（{{ stay_label }}）
{{ prev_count }}件 → {{ curr_count }}件

{% for h in current_hotels %}
🏨 {{ h.name }} / {{ h.price_text }}円
{% endfor %}

👉 {{ search_url }}
```

### 書き換えたら見た目を確認する

```bash
python main.py --preview-mail
```

ダミーデータで文面を組み立てて表示します（メールは送りません）。
HTML版は `preview_mail.html` に書き出されるので、ブラウザで開いて確認できます。

> テンプレートの書き方を間違えても監視は止まりません。
> その場合は内蔵の予備文面で通知され、ログにエラーが記録されます。

## 監視条件を変える

`config.yaml` を書き換えます。

```yaml
watches:
  - id: aomori_20260920        # state のファイル名になる（半角英数字）
    name: "青森市周辺"          # メールに出る表示名
    enabled: true
    large_class_code: japan
    middle_class_code: aomori
    small_class_code: aomori
    checkin: "2026-09-20"
    checkout: "2026-09-21"
    adult_num: 2
    room_num: 1
    notify_on: both            # both / increase / decrease
```

### エリアコードの調べ方

楽天トラベルで検索した結果ページのURLを見ます。

```
...&f_dai=japan&f_chu=aomori&f_shou=aomori&...
     ↓            ↓             ↓
large_class_code  middle_class_code  small_class_code
```

例えば札幌市内なら `f_chu=hokkaido&f_shou=sapporo` なので、
`middle_class_code: hokkaido` / `small_class_code: sapporo` になります。

### 複数の条件を同時に監視する

`watches:` の下にそのまま並べるだけです。`id` は重複させないでください。

```yaml
watches:
  - id: aomori_20260920
    name: "青森市周辺"
    middle_class_code: aomori
    small_class_code: aomori
    checkin: "2026-09-20"
    checkout: "2026-09-21"

  - id: hakodate_20261010
    name: "函館"
    middle_class_code: hokkaido
    small_class_code: hakodate
    checkin: "2026-10-10"
    checkout: "2026-10-11"
```

### 通知する変化の種類

| 設定 | 動き |
|---|---|
| `notify_on: both` | 増えても減っても通知（既定） |
| `notify_on: increase` | 増えたときだけ通知 |
| `notify_on: decrease` | 減ったときだけ通知 |
| `notify_on_hotel_change: false` | 件数が同じで宿だけ入れ替わった場合は通知しない |

## 無料枠について

### なぜ Public リポジトリなのか

| リポジトリ | Actions の無料枠 | 5分間隔（月約8,640分）は？ |
|---|---|---|
| **Public** | **無制限** | 完全に無料 |
| Private | 月2,000分（Freeプラン） | **大幅に超過して課金される** |

GitHub Actions は1回の実行を **1分単位に切り上げ** て計上します。
5分間隔だと 1日288回 × 30日 = 月8,640回。Private では無料枠の4倍以上になります。
**Public なら実行時間が無制限なので、何回実行しても無料です。**

Public でも `Secrets` の中身は公開されません。また、リポジトリに保存されるのは
宿名・件数・日時だけで、メールアドレスやパスワードは一切書き込まれません
（これはテスト `test_state_never_contains_secrets` で保証しています）。

### Private で使いたい場合

監視間隔を30分に落とせば無料枠に収まります（月約1,440分）。
`.github/workflows/watch.yml` の cron を書き換えてください。

```yaml
    - cron: "*/30 * * * *"
```

| 間隔 | 月の実行回数 | 月の消費 | Private無料枠(2,000分) |
|---|---|---|---|
| 5分 | 約8,640回 | 約8,640分 | 大幅に超過する |
| 10分 | 約4,320回 | 約4,320分 | 超過する |
| 20分 | 約2,160回 | 約2,160分 | わずかに超過 |
| **30分** | 約1,440回 | 約1,440分 | **収まる** |
| 60分 | 約720回 | 約720分 | 余裕で収まる |

Public リポジトリならこの表は関係ありません（すべて無料）。

### 間隔の下限とスケジュールの遅延について

**5分が GitHub Actions で設定できる最短間隔です。** これより短い cron を書いても、
5分間隔に丸められます。

このプロジェクトでは `*/5`（0,5,10…分）ではなく **`2-59/5`（2,7,12…分）** を使っています。
毎時0分ちょうどは GitHub 全体で実行が集中して最も遅延しやすいため、そこを避けています。
実行回数は同じ12回/時のまま、遅延の影響を減らせます。

また、スケジュール実行は混雑時に **数分〜十数分遅れる** ことがあり、
まれにスキップされます。`*/5` と設定しても、実際には5〜15分間隔で動くことがあり、
**厳密な5分間隔は保証されません。** そのため10分設定との実効的な差は、
設定値ほど大きくならない場合があります。

なお、間隔を短くすると楽天トラベルへのアクセス回数も増えます
（5分間隔で1日288回）。これ以上短くすることは技術的にも礼儀の面でも避けてください。

## 止まらないようにする（60日ルール）

GitHub は **60日間まったく更新のないリポジトリ** のスケジュール実行を自動停止します。
空室に変化がない状態が2ヶ月続くと監視が止まってしまうため、
週に1度 `heartbeat.txt` を更新してコミットする仕組みを入れてあります。

念のため、たまに **Actions** タブを開いて実行が続いているか確認してください。
停止していた場合は、画面に出る「Enable workflow」ボタンで再開できます。

## 自分のPCで動かす場合

普段は不要です。文面の確認やデバッグに使います。

```bash
# 1. 依存パッケージを入れる
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt

# 2. .env を用意する
copy .env.example .env          # Windows
#   → .env をメモ帳などで開き、Gmailアドレス・アプリパスワード・宛先を記入

# 3. 使う
python main.py --preview-mail   # 文面だけ確認（送信しない）
python main.py --test-mail      # テストメールを1通送る
python main.py --dry-run        # 実際に取得するがメールは送らない
python main.py                  # 本番と同じ動作
```

### タスクスケジューラで動かしたい場合

> **GitHub Actions と同時に有効にしないでください。** 同じメールが二重に届きます。
> どちらか一方だけを使ってください。

1. 「タスク スケジューラ」を開く →「タスクの作成」
2. **全般** タブ：「ユーザーがログオンしているかどうかにかかわらず実行する」
3. **トリガー** タブ：新規 →「毎日」→ 詳細設定で
   「繰り返し間隔: 5分間」「継続時間: 無期限」
4. **操作** タブ：新規 → プログラム
   - プログラム: `（このフォルダ）\.venv\Scripts\pythonw.exe`
   - 引数: `main.py`
   - 開始（作業フォルダ）: このフォルダのパス
5. **条件** タブ：「タスクを実行するためにスリープを解除する」にチェック

`pythonw.exe` を使うと黒いコンソール窓が出ません。

**この方式ではPCの電源が入っている間しか監視されません。**
電源を切っている間も監視したい場合は GitHub Actions を使ってください。

## 監視を止める

| やりたいこと | 方法 |
|---|---|
| 一時的に止める | Actions タブ →「空室監視」→ 右上の `...` → **Disable workflow** |
| 特定の条件だけ止める | `config.yaml` のその条件を `enabled: false` にする |
| 完全に止める | リポジトリを削除する |

監視が終わったら、Gmail のアプリパスワードも削除しておくと安全です
（<https://myaccount.google.com/apppasswords>）。

## 困ったときは

### メールが届かない

1. **Yahoo!メールの迷惑メールフォルダ** を確認する（最も多い原因）
2. Actions タブでワークフローが成功しているか確認する
3. 「初回実行のため通知しません」と出ていないか確認する
   → 初回は基準を保存するだけでメールは送りません。正常です
4. 「変化なし」と出ていないか確認する
   → 件数が変わっていなければメールは送りません。正常です

### `Gmail の認証に失敗しました` と出る

- 通常のログインパスワードを設定していませんか？ **アプリパスワード** が必要です
- 2段階認証が有効になっているか確認してください
- Secrets の `GMAIL_APP_PASSWORD` を、余計な文字が入っていないか確認して登録し直す

### `GMAIL_ADDRESS が設定されていません` と出る

Secrets の名前が間違っている可能性があります。大文字・小文字も一致させてください。

### `検索結果ページから件数を読み取れませんでした`

楽天トラベル側のページ構造が変わった可能性があります。
`rakuten_watch/fetchers.py` の `_RE_TOTAL` などの抽出パターンを直す必要があります。
このエラーが12回（約1時間）続くと、エラーの内容を書いたメールが届きます（1日1通まで）。

### スケジュールが動いていない

- **Actions** タブでワークフローが無効化されていないか確認する（60日ルール）
- リポジトリのデフォルトブランチ（`main`）に `watch.yml` があるか確認する
  スケジュール実行はデフォルトブランチのものしか動きません

### 同じメールが何度も届く

GitHub Actions と、PCのタスクスケジューラの両方が動いていませんか？
どちらか一方だけを有効にしてください。

## テスト

```bash
pytest tests -q
```

差分検知・重複通知の抑制・テンプレート描画・メールヘッダのエンコード・
設定ファイルの検証などを確認します。
ネットワークにも Gmail にも接続しないので、いつでも実行できます。
